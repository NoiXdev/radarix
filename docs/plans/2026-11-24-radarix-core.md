# Radarix Core Implementation Plan (Plan 1 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A locally built Radarix app that signs in to GitHub, lets the user choose repos, syncs their issues and PRs within the rate limit, and shows them in the main window as new / updated / seen with filters.

**Architecture:** All logic lives in the local Swift package `RadarixKit` (GitHub client, sign-in, state rules, sync, persistence, filtering, and an observable controller), tested with `swift test`. The app target is a thin SwiftUI layer over `RadarixController`. The Xcode project is generated by XcodeGen from `project.yml`, because Plan 2 adds a widget extension.

**Tech Stack:** Swift 6.4 / Xcode 27.2, SwiftUI, Observation, Swift Testing, XcodeGen, GitHub REST API v3, macOS Keychain (Security framework). No third-party dependencies.

**Spec:** `docs/specs/2026-11-24-radarix-design.md`

**Roadmap:**
- **Plan 1 (this):** project, core logic, sign-in, settings, main window.
- **Plan 2:** menu bar extra, notifications, widget extension (App Group snapshot, deep links), open at login, app icon and menu bar glyph from `docs/design/`.
- **Plan 3:** GitHub repo `NoiXdev/radarix`, CI + release workflows from macSCP, Homebrew cask, then docs (noix-docs), project page and launch post (noix.dev).

## Global Constraints

- Deployment target **macOS 15.0**. Bundle id `dev.noix.radarix`. URL scheme `radarix` (registered in Plan 2).
- App Group id `$(TeamIdentifierPrefix)dev.noix.radarix` (team-prefixed, so no provisioning profile is needed for Developer ID).
- **Credentials only in the Keychain**, service `dev.noix.radarix.credential`, account = GitHub account id. Never in defaults, files, logs or the shared container.
- **Item state is keyed by numeric GitHub ids** (repo id + issue number), never by `owner/name`, so renames and transfers keep state.
- **All code, comments, test names, commit messages in English.** UI strings in `App/Resources/Localizable.xcstrings`, languages `en` (source) and `de` (addresses the user as "du"). `RadarixKit` contains no user-facing strings; the app maps Kit errors to text.
- OAuth scopes exactly `repo read:org`. OAuth client id comes from build setting `RADARIX_OAUTH_CLIENT_ID` (Info.plist key `GitHubOAuthClientID`); when empty, device-flow sign-in is disabled and the token path still works.
- Default refresh interval **300 s**; allowed values 120, 300, 600, 900, 1800 s.
- Defaults: layout `.sidebar`, bot display `.badge`, bot notifications off, updated notifications off, open at login off, archived repos hidden, every owner `.off` until the user chooses.
- Conventional Commits. Commit footer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A repo with thousands of issues added for the first time:** the baseline must page through open items only, mark them seen, not notify, and not stall other repos. Pinned in Task 7 (`baselineFetchesOpenItemsOnlyAndPages`).
2. **Idle repos must cost nothing:** the `since` value in the issues URL must stay identical between syncs while nothing changes, otherwise ETags never match and every sync burns quota. Pinned in Task 7 (`unchangedRepoSendsSameURLAndGets304`).
3. **Credential revoked mid-session:** a 401 must keep every setting and seen state and switch to "sign in again", never wipe or loop. Pinned in Task 7 (`unauthorizedKeepsDataAndFlagsReauth`) and Task 8.
4. **Offline / server errors / rate limited:** keep last data, record the failure per repo, back off until `X-RateLimit-Reset`, no retry storm. Pinned in Task 7 (`rateLimitedStopsAndReportsReset`, `networkErrorKeepsPreviousItems`).
5. **Org that restricts OAuth Apps or needs SSO:** a 403 on an org's repo list must surface as an owner access issue with the org name, not as an empty org. Pinned in Task 6 (`orgReposForbiddenBecomesAccessIssue`).

```swift
public enum SyncFailure: Sendable, Equatable { case network(String), notFound, http(Int), decoding(String) }
public struct SyncReport: Sendable, Equatable {
    public var newItems: [Item] = []                 // became .new in this sync (never on baseline)
    public var updatedItems: [Item] = []             // became .updated in this sync
    public var repoFailures: [RepoID: SyncFailure] = [:]
    public var ownerIssues: [String: OwnerAccessIssue] = [:]
    public var needsReauth = false
    public var rateLimitedUntil: Date?
    public var rateLimit: RateLimit?
    public var availableRepos: [String: [RepoRef]] = [:]
}
public struct SyncEngine: Sendable {
    public init(api: GitHubAPI, now: @Sendable @escaping () -> Date = Date.init)
    public func sync(_ account: AccountData, owners: [OwnerRef]) async -> (AccountData, SyncReport)
}
```

Algorithm (per sync): refresh repo lists per non-`.off` owner (`Fetch.notModified` keeps the previous list); resolve watched repos; drop `RepoState` of repos no longer watched; for each watched repo, sequentially:
1. No `baselineAt` → `items(.openForBaseline)` → `ItemStateEngine.baseline`, set `baselineAt = now`, `highWaterMark = max(updatedAt)`. No report entries.
2. Otherwise → `items(.changed(since: highWaterMark ?? baselineAt))`. `.notModified` → nothing. `.fresh` → for each item: skip if `updatedAt` equals the stored record's; call `hasOtherActivity(since: record.seenAt)` only when `needsActivityCheck`; a thrown error there → `otherActivity: nil`; then `apply`. Raise `highWaterMark` to the newest `updatedAt`.
3. `openPullDetails` → merge `isDraft` / `requestedReviewers` into PR records.

Errors: `.unauthorized` → stop, `needsReauth = true`, return the input account unchanged except work already done. `.rateLimited(resetAt)` → stop, `rateLimitedUntil = resetAt`. `.forbidden` on an org's repo list → `ownerIssues[login] = .restricted(message:)`, keep previous repos of that owner. Other errors → `repoFailures[id]`, `RepoState.lastFailure`, continue with the next repo, previous records kept.

  - `newItemByOtherIsReported`, `itemByViewerIsNotReported`
  - `updatedOnlyAfterActivityCheck` (seen item moves; probe true → in `updatedItems`; probe false → stays seen and not reported)
